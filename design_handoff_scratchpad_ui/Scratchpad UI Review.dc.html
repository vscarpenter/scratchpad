Scratchpad — UI review

vscarpenter/scratchpad @ main

Read before writing anything: index.html, all 3,325 lines of app.css, Inkwell tokens v3.0.0 “Soft Glass”, inkwell-components.css, PRODUCT.md, and your existing ui-design-suggestions.md. Every mockup below is drawn with real token values — no new colors, no web fonts, no build step.

What's already good

Token discipline is unusually strong — the dark cascade is byte-parallel and AA-checked, and almost nothing in app.css is a one-off value. The two-pane glass shell reads calm. Command palette, focus mode, daily note, wikilinks and revision history are genuinely power-user grade.

The through-line of all five

The app has grown a lot of capability, and nearly all of it landed in two places: the sidebar header and the About dialog. The header now costs ~290px before the first note, and About is doing six jobs at once. The chrome has started competing with the writing.

1 Five ideas, highest impact first each shown as today vs. proposed, at 1:1
1a

Collapse the five-row sidebar header into two

The header stacks brand, search, a two-row action block, a segmented view switch and a Folders/Recent pair — ≈290px of chrome in a 302px-wide column, using three different toggle idioms back to back. “Tags” also sits inside the view segmented control even though it opens a dialog rather than switching views, so the control lies about what it does.

1b

Turn the footer slogan into a live backup status

In a local-only app, export is the durability story — and all four export paths live behind an ⓘ button labelled “About Scratchpad”, next to diagnostics, an erase-everything zone, and the shortcut list. Meanwhile the permanent footer repeats a promise the user already read. Trade the slogan for the one fact that changes: when they last backed up.

Right now .note-row-tags { display: none } except on .is-active, and the excerpt is clamped to one line until a row is active. So the list is only informative about the note you're already reading — and tags, the main organising device, are invisible exactly when you're scanning for one.

1d

Stop the page from reflowing when you press Edit

Reading is 32px bold sans over sans body; editing is 14px/1.85 var(--mono). Every ⌘S changes typeface, size, line-height and line breaks — the one moment the tool is least invisible. Separately, --serif is defined in the tokens and used nowhere, while PRODUCT.md asks for “serif headings and generous whitespace”.

Identical metrics — nothing moves on ⌘S

The rule. Serif for the note title and rendered h2/h3 — all system faces, so no web font and no CSP change. Body 16.5px/1.75 with a 68ch measure, and the textarea uses the same family, size, leading and measure. Mono survives where it earns it: code spans, code blocks, the kbd hints.

If you'd rather keep mono for writing — plenty of markdown-fluent people would — then keep it, but match the metrics (mono 15px/1.75 sits at the same rhythm) so the reflow still disappears. That's the part that matters; the serif is the upside.
1e

Split the editor rail: document actions up top, formatting by the text

One flex-wrap: wrap row holds Back, breadcrumb, unsaved chip, pin, share, a divider, four format chips, Edit/Save, Restore, Delete forever and overflow. Entering edit mode adds ~120px of chips, so the rail reshuffles or wraps to two lines exactly when you're trying to type. Focus mode — the best thing in the app — has no button at all.

What moved. Pin and Share go into ⋯ (which already holds Move, Duplicate, History, Export, Delete). Focus mode gets the one icon slot they vacate. Restore / Delete-forever only exist in Trash, so they can live in ⋯ too and stop budgeting width in the common case. The rail becomes fixed: back, breadcrumb, state, focus, primary, overflow.

Why it's also prettier. Drop flex-wrap and the toolbar can never break into two lines. The floating format pill reuses the glass-pill treatment already in the tokens (--glass-bg-pill, --shadow-pill-float), and there's finally room for the three markdown affordances people actually reach for.

One thing to decide before any of this

PRODUCT.md names “glassmorphism, gradient hero text, purple-to-blue everything” as an anti-reference, and asks for serif headings and restraint. Inkwell 3.0 “Soft Glass” is frosted panels, a gradient brand glyph, a two-hue wash, and a glowing indigo shadow under every primary button — its own header says it “deliberately retires the flat no-shadow surface”. Both are coherent; they just aren't the same product. The five ideas above work either way, but 1d is the one that makes the answer visible, so it's worth settling first: is Soft Glass the direction, or is the product doc?
